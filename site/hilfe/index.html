Spielebibliothek

So funktioniert die Spielebibliothek

  • Spielen: Spiel auf der Startseite auswählen → „Spielen“. Mit „Vollbild“ füllt es den ganzen Bildschirm.
  • Speichern passiert automatisch auf dem Server – du kannst auf jedem Gerät weiterspielen, auf dem du angemeldet bist.
  • Bestenliste: steht rechts neben dem Spiel, dein Eintrag ist hervorgehoben. Bei manchen Spielen gibt es ältere „Seasons“ zum Nachschauen.
  • Anmeldung: per E-Mail-Code, gilt eine Woche pro Gerät.
  • Etwas geht nicht oder du hast eine Idee? Menü (oben rechts auf deinen Namen) → Anträge → „Fehler melden“ oder „Wunsch / Idee“.

So kommt dein Spiel in die Bibliothek

  1. Spiel bauen – am einfachsten mit KI. Kopiere den Prompt-Block unten in deinen Prompt.
  2. Testen – index.html lokal im Browser öffnen. Speichern geht dort nur bis zum Neuladen, das ist normal.
  3. Als ZIP packen – den Spielordner komprimieren. Mac: Rechtsklick → „Komprimieren“. Windows: Rechtsklick → „Senden an“ → „ZIP-komprimierter Ordner“.
  4. Hochladen – upload.cuby0401.uk öffnen, mit dem E-Mail-Code anmelden, dann mit deinem Upload-Passwort (bitte nicht im Browser speichern). ZIP auswählen, Ordnernamen prüfen, „Als Entwurf“ lassen, „Hochladen“.
  5. Entwurf testen – auf der Upload-Seite „Testen“ (oder Menü → Meine Spiele → „Entwurf testen“). Nur du siehst den Entwurf; er startet mit einer Kopie deines Spielstands, Bestenlisten-Einträge zählen noch nicht.
  6. Veröffentlichen – auf der Upload-Seite. Jetzt sehen es alle; die bisherige Version wird aufgehoben.

Hochladen können nur Entwickler mit Upload-Konto. Wenn du auch Spiele bauen willst, melde dich bei Seb.

Dein Menü (oben rechts auf deinen Namen klicken)

  • Einstellungen: Sortierung der Übersicht (alphabetisch, zuletzt gespielt, neueste), Großansicht (Spiel füllt das Fenster), Bestenliste neben dem Spiel ein/aus. Gilt auf allen deinen Geräten. Mit dem ★ auf einer Kachel heftest du Lieblingsspiele oben an.
  • Meine Spielstände: alle deine Spielstände je Spiel – mit „Neu anfangen“ löschst du sie für ein Spiel (Bestenlisten-Einträge bleiben; Seb kann die letzten 5 Stände wiederherstellen).
  • Anträge: Fehler melden, Wunsch / Idee, Spielstand wiederherstellen lassen oder Sonstiges. Seb bekommt den Antrag direkt; Status und seine Antwort siehst du unter „Anträge“.
  • Abmelden: z. B. an einem fremden Rechner. Danach ist ein neuer E-Mail-Code nötig.

Zusätzlich für Entwickler:

  • Meine Spiele: deine Spiele mit Statistik – wie viele Spieler, wann zuletzt gespielt, Bestenlisten-Einträge, Fehlerberichte und „Entwurf testen“. Mit „Neue Season“ startest du eine leere Bestenliste (die alte bleibt abrufbar) – ohne neue game.json.
  • Anträge zusätzlich für deine Spiele: Bestenliste zurücksetzen, Spiel löschen oder umbenennen.

Was du selbst einstellen kannst – und was nicht

Selbst (im Spiel oder in der game.json)Nur über Antrag an Seb

  • Eigene Darstellung der Bestenliste im Spiel

Fest bleibt immer: Wer angemeldet ist, steht mit seinem Namen in der Bestenliste – einmal, mit seinem besten Eintrag. Spiele können nicht auf andere Spiele, die Anmeldung oder fremde Server zugreifen.

Regeln

  1. Ein Ordner pro Spiel, index.html direkt darin. Im ZIP darf der Ordner drumherum sein – das wird erkannt.
  2. Nur relative Pfade: ./sprites/held.png, nicht /sprites/held.png. Einzige Ausnahme: /lib/gamesave.js.
  3. Nur fertige Dateien. Mit Vite/React: den Ordner dist/ hochladen, vorher base: './' setzen.
  4. Keine externen Server. Keine CDNs – Bibliotheken wie three.js oder Phaser als Datei mitliefern. Keine Aufrufe ins Internet, kein eigener Server-Code. Die Bibliothek blockiert das sonst.
  5. Speichern mit GameSave. localStorage funktioniert auch (wird automatisch auf dem Server gespeichert), aber nur mit GameSave gibt es Bestenlisten und saubere Updates.
  6. Updates immer in denselben Ordner – also beim Hochladen denselben Ordnernamen nehmen. Neuer Ordnername = neues Spiel, Spielstände und Bestenliste wären weg.
  7. Spielstände bei Updates absichern: beim Laden standard und migration angeben und bei jeder Änderung der Speicherstruktur saveVersion erhöhen – siehe Updates.
  8. Erlaubte Dateitypen: html, js, mjs, css, json, png, jpg, gif, webp, svg, ico, mp3, ogg, wav, m4a, mp4, webm, woff, woff2, ttf, otf, wasm, txt, glb, gltf, bin. Alles andere (z. B. .exe, Skripte, versteckte Dateien) wird beim Hochladen übersprungen.
  9. Größe: höchstens 100 MB pro ZIP.
  10. Nach Logins fragen nur Cloudflare (E-Mail-Code) und die Upload-Seite. Fragt ein Spiel nach einem Passwort, ist etwas faul – bitte Seb Bescheid geben.

GameSave – Speichern und Bestenliste

<script src="/lib/gamesave.js"></script>   <!-- als ERSTES Script -->

await GameSave.save("spielstand", { level: 3, punkte: 500 });
const { data, version } = await GameSave.load("spielstand");  // data = null, wenn nichts da
await GameSave.remove("spielstand");
await GameSave.submitScore(1250);                // nur mit Bestenliste in game.json
const top = await GameSave.leaderboard();        // [{ player: "paul", score: 1250 }, …]
const ich = await GameSave.player();             // "paul"
GameSave.available                               // false beim lokalen Testen

Alle Aufrufe können fehlschlagen (z. B. offline) – Fehler mit try/catch abfangen. Keys: Buchstaben, Ziffern, . _ : -, max. 100 Zeichen. Ein Spielstand darf höchstens 256 KB groß sein.

Entwürfe, Versionen und Fehlerberichte

  • Entwurf: Jeder Upload kann erst als Entwurf landen. Testen in der Bibliothek, dann veröffentlichen oder verwerfen. Ideal für Updates: Mit der Kopie deines Spielstands siehst du sofort, ob deine Migration funktioniert – ohne den echten Stand zu gefährden.
  • Versionen: Beim Veröffentlichen (oder „Sofort veröffentlichen“) wird die bisherige Version aufgehoben – die letzten 5. Auf der Upload-Seite unter „Ältere Versionen“ → „Zurücksetzen“ ist ein kaputtes Update in Sekunden rückgängig gemacht. Spielstände und Bestenliste bleiben davon unberührt.
  • Fehlerberichte: JavaScript-Fehler, die beim Spielen auftreten, werden automatisch gemeldet – gleiche Fehler zusammengefasst, ohne Spielernamen, nur mit Browser und Gerätetyp. Du findest sie unter Menü → Meine Spiele → „Fehlerberichte“ mit Datei, Zeile und Stacktrace. Fehler aus dem Entwurf sind extra gekennzeichnet.

Updates: was mit Spielständen passiert

  • Spielstände liegen nicht im Spielordner, sondern auf dem Server – getrennt nach Spieler und Spiel (dein-name/ordnername). Ein Update (gleiches ZIP-Verfahren, gleicher Ordnername) ersetzt nur die Spieldateien; Fortschritt und Bestenliste bleiben. Selbst nach Löschen und erneutem Hochladen unter demselben Namen sind sie wieder da.
  • Das Problem: Dein neues Spiel liest Spielstände, die eine alte Version geschrieben hat. Hatte das Inventar früher 2 Plätze und jetzt 5, oder heißt ein Feld jetzt anders, muss das neue Spiel damit umgehen können.
  • Die Lösung: saveVersion in der game.json + Standardwerte + Umwandlungsschritte beim Laden. Jeder Spielstand merkt sich, mit welcher saveVersion er geschrieben wurde.
// game.json: "saveVersion": 3   ← bei jeder Strukturänderung um 1 erhöhen

const { data, migriert } = await GameSave.load("spielstand", {
  // für neue Spieler UND für Felder, die es früher noch nicht gab (wird automatisch ergänzt)
  standard: { level: 1, inventar: ["", "", "", "", ""], einstellungen: { ton: true } },
  // Umwandlung alter Stände, Schritt für Schritt – Schlüssel = saveVersion, zu der umgewandelt wird
  migration: {
    2: (alt) => ({ ...alt, inventar: [...alt.inventar, "", "", ""] }),            // 2 → 5 Plätze
    3: (alt) => { const { punkte, ...rest } = alt; return { ...rest, gold: punkte ?? 0 }; },  // umbenannt
  },
});
if (migriert) await GameSave.save("spielstand", data);   // umgewandelten Stand gleich speichern
  • Fehlende Felder in Objekten werden automatisch aus standard ergänzt. Arrays werden nicht verändert – Längenänderungen gehören in eine migration.
  • Ein alter Stand mit saveVersion 1 läuft durch Schritt 2 und 3. Schlägt ein Schritt fehl, gibt load einen Fehler zurück – der Spielstand wird dabei nicht verändert.
  • Einfache Spiele ohne Strukturänderung brauchen nur standard. load(key) ohne Optionen funktioniert weiter wie bisher.
  • Die letzten 5 Stände jedes Spielstands sind gesichert – bei einem kaputten Update kann Seb zurückdrehen.
  • Eine vollständige Vorlage ist das Spiel „Bestenlisten-Vorlage“ in der Bibliothek (Quelltext ansehen: Rechtsklick im Spiel → Rahmenquelltext).

Bestenliste gestalten

Fest (bestimmt die Bibliothek): Der Spielername kommt aus der Anmeldung, jeder Spieler steht einmal drin (mit seinem besten Eintrag), bei Gleichstand gewinnt, wer es zuerst geschafft hat, höchstens ein Eintrag pro Sekunde, Seasons. Frei (bestimmst du): ob es eine Bestenliste gibt, welcher Wert über den Platz entscheidet, Reihenfolge, Spalten und Formate – und wie du sie im Spiel darstellst.

"leaderboard": {
  "enabled": true,                 // false = keine Bestenliste
  "rangiertNach": "level",         // dieser Wert entscheidet den Platz (Zahl-Spalte), sonst "score"
  "order": "desc",                 // "desc" = mehr ist besser, "asc" = weniger ist besser
  "spalten": [                     // bis zu 6 Spalten
    { "key": "level", "label": "Level" },
    { "key": "items", "label": "Gegenstände" },
    { "key": "zeit",  "label": "Spielzeit", "format": "zeit" },
    { "key": "held",  "label": "Held",      "format": "text" }
  ]
}
await GameSave.submitScore({ level: 12, items: 48, zeit: 5430000, held: "Mira" });
const top = await GameSave.leaderboard();
// [{ rank: 1, player: "paul", score: 12, werte: { level: 12, items: 48, zeit: 5430000, held: "Mira" } }, …]
  • Formate: zahl (Standard, 1.234), dezimal (12,50), zeit (Millisekunden → 1:23,4 bzw. 1:02:03), text (höchstens 40 Zeichen, kann nicht rangieren).
  • Einfach bleibt einfach: ohne spalten reicht submitScore(1250); mit "label" und "format" auf oberster Ebene gestaltest du die Score-Spalte.
  • Nur in der game.json eingetragene Spalten werden angenommen – ein Tippfehler im Schlüssel gibt eine Fehlermeldung.
  • Die Bibliothek zeigt die Spalten neben dem Spiel an. Im Spiel kannst du die Liste mit GameSave.leaderboard() beliebig selbst darstellen.

game.json

{
  "title": "Snake",
  "description": "Klassisches Snake mit Power-ups",
  "thumbnail": "thumb.png",
  "saveVersion": 1,
  "leaderboard": { "enabled": true, "order": "desc", "label": "Punkte" },
  "leaderboardSeason": 1
}
  • order: "desc" = mehr ist besser, "asc" = weniger ist besser (z. B. Zeit).
  • leaderboardSeason erhöhen, wenn ein Update das Spiel deutlich leichter oder schwerer macht – dann beginnt eine neue Bestenliste, die alte bleibt abrufbar.
  • Der Autor kommt immer aus deinem Benutzernamen, nicht aus der game.json.

Prompt-Block zum Kopieren

In deinen KI-Prompt einfügen, zusätzlich zur Beschreibung deines Spiels. 
Baue das Spiel als statische Web-App für die Spielebibliothek:
- index.html im Hauptordner, alle Pfade relativ (./…), keine CDNs, alle Bibliotheken als Datei mitliefern, kein Server-Code, keine Netzwerkaufrufe nach außen.
- Binde <script src="/lib/gamesave.js"></script> als erstes Script ein und speichere Fortschritt mit await GameSave.save(key, data) / const {data, version} = await GameSave.load(key). Fange Fehler von GameSave ab. GameSave.available ist false beim lokalen Testen – das Spiel muss trotzdem laufen.
- Spielstände bei Updates absichern: lade mit await GameSave.load(key, { standard: {...alle Felder mit Startwerten...}, migration: { 2: (alt) => neu, ... } }), erhöhe "saveVersion" in der game.json bei jeder Änderung der Speicherstruktur und ergänze dann einen migration-Schritt für diese Version. Felder nie stillschweigend umbenennen oder anders verwenden.
- Für Highscores: await GameSave.submitScore(zahl) – oder mit mehreren Werten: await GameSave.submitScore({ level, items, zeit }) und dazu in der game.json unter leaderboard "rangiertNach" (entscheidender Zahlenwert) und "spalten": [{ "key": "...", "label": "...", "format": "zahl|dezimal|zeit|text" }]. await GameSave.leaderboard() liefert [{rank, player, score, werte}].
- Lege eine game.json an: {"title": "...", "description": "...", "thumbnail": "thumb.png", "saveVersion": 1, "leaderboard": {"enabled": true, "order": "desc", "label": "Punkte"}, "leaderboardSeason": 1} und erstelle ein Vorschaubild thumb.png oder thumb.svg im Format 16:9.
- Wenn du Elemente mit dem hidden-Attribut ein- und ausblendest, ergänze im CSS [hidden] { display: none !important; } – sonst bleiben Overlays mit display:flex/grid sichtbar.
- Ändere bei späteren Updates die Struktur gespeicherter Daten nie ohne Migration: neue Felder mit Standardwerten, nichts umbenennen oder löschen. Wenn sich die Struktur ändert, erhöhe saveVersion und wandle alte Stände beim Laden um.
- Nur diese Dateitypen verwenden: html, js, css, json, png, jpg, gif, webp, svg, mp3, ogg, wav, woff2, wasm, glb, gltf.

Häufige Fragen

Ein Spiel lädt nicht, hängt oder hat einen Fehler.
Seite neu laden. Hilft das nicht: Menü → Anträge → „Fehler melden“ und kurz beschreiben, was passiert.
Mein Spielstand ist weg.
Menü → Anträge → „Spielstand wiederherstellen“ – die letzten 5 Stände jedes Spielstands sind gesichert.
Mein Spiel zeigt nur eine weiße Fläche.
Meist ein absoluter Pfad (/assets/…) oder eine Bibliothek vom CDN. Beides geht hier nicht – siehe Regeln 2 und 4.
Ein Overlay oder Menü verschwindet nicht.
Siehe die hidden-Zeile im Prompt-Block.
Mein Spielstand ist nach einem Update weg oder kaputt.
Wurde ein anderer Ordnername verwendet? Hat sich die Speicherstruktur geändert, ohne saveVersion zu erhöhen und einen migration-Schritt zu ergänzen (siehe Updates)? Sonst bei Seb melden – die letzten 5 Stände jedes Spielstands sind gesichert.
Mein Bestenlisten-Eintrag wird abgelehnt.
Steht jeder Schlüssel aus submitScore({...}) in leaderboard.spalten? Ist der Wert aus rangiertNach dabei und eine Zahl? Die Fehlermeldung von submitScore nennt den Grund.
Mein Update ist kaputt.
Upload-Seite → beim Spiel „Ältere Versionen“ → „Zurücksetzen“. Nächstes Mal erst als Entwurf hochladen und testen.

Ich habe ein Update gemacht, das Spiel ist jetzt viel leichter.

Ich will in einem Spiel von vorn anfangen.
Menü → Meine Spielstände → „Neu anfangen“ beim Spiel.
Ich habe eine Idee für ein Spiel oder die Bibliothek.
Menü → Anträge → „Wunsch / Idee“.
Ich möchte selbst Spiele bauen.
