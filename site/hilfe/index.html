So kommt dein Spiel in die Bibliothek

  1. Spiel bauen – am einfachsten mit KI. Kopiere den Prompt-Block unten in deinen Prompt.
  2. Testen – index.html lokal im Browser öffnen. Speichern geht dort nur bis zum Neuladen, das ist normal.
  3. Als ZIP packen – den Spielordner komprimieren. Mac: Rechtsklick → „Komprimieren“. Windows: Rechtsklick → „Senden an“ → „ZIP-komprimierter Ordner“.
  4. Hochladen – upload.cuby0401.uk öffnen, mit dem E-Mail-Code anmelden, dann mit deinem Upload-Passwort (bitte nicht im Browser speichern). ZIP auswählen, Ordnernamen prüfen, „Hochladen“.
  5. Spielen – hier die Seite neu laden, dein Spiel ist da.

Hochladen können nur Entwickler mit Upload-Konto. Wenn du auch Spiele bauen willst, melde dich bei Seb.

Regeln

  1. Ein Ordner pro Spiel, index.html direkt darin. Im ZIP darf der Ordner drumherum sein – das wird erkannt.
  2. Nur relative Pfade: ./sprites/held.png, nicht /sprites/held.png. Einzige Ausnahme: /lib/gamesave.js.
  3. Nur fertige Dateien. Mit Vite/React: den Ordner dist/ hochladen, vorher base: './' setzen.
  4. Keine externen Server. Keine CDNs – Bibliotheken wie three.js oder Phaser als Datei mitliefern. Keine Aufrufe ins Internet, kein eigener Server-Code. Die Bibliothek blockiert das sonst.
  5. Speichern mit GameSave. localStorage funktioniert auch (wird automatisch auf dem Server gespeichert), aber nur mit GameSave gibt es Bestenlisten und saubere Updates.
  6. Updates immer in denselben Ordner – also beim Hochladen denselben Ordnernamen nehmen. Neuer Ordnername = neues Spiel, Spielstände und Bestenliste wären weg.
  7. Speicherstruktur nicht ohne Migration ändern: neue Felder mit Standardwerten, nichts umbenennen oder löschen; bei Strukturänderung saveVersion in der game.json erhöhen und alte Stände beim Laden umwandeln.
  8. Erlaubte Dateitypen: html, js, mjs, css, json, png, jpg, gif, webp, svg, ico, mp3, ogg, wav, m4a, mp4, webm, woff, woff2, ttf, otf, wasm, txt, glb, gltf, bin. Alles andere (z. B. .exe, Skripte, versteckte Dateien) wird beim Hochladen übersprungen.
  9. Größe: höchstens 100 MB pro ZIP.
  10. Nach Logins fragen nur Cloudflare (E-Mail-Code) und die Upload-Seite. Fragt ein Spiel nach einem Passwort, ist etwas faul – bitte Seb Bescheid geben.

GameSave – Speichern und Bestenliste

<script src="/lib/gamesave.js"></script>   <!-- als ERSTES Script -->

await GameSave.save("spielstand", { level: 3, punkte: 500 });
const { data, version } = await GameSave.load("spielstand");  // data = null, wenn nichts da
await GameSave.remove("spielstand");
await GameSave.submitScore(1250);                // nur mit Bestenliste in game.json
const top = await GameSave.leaderboard();        // [{ player: "paul", score: 1250 }, …]
const ich = await GameSave.player();             // "paul"
GameSave.available                               // false beim lokalen Testen

Alle Aufrufe können fehlschlagen (z. B. offline) – Fehler mit try/catch abfangen. Keys: Buchstaben, Ziffern, . _ : -, max. 100 Zeichen. Ein Spielstand darf höchstens 256 KB groß sein.

game.json

{
  "title": "Snake",
  "description": "Klassisches Snake mit Power-ups",
  "thumbnail": "thumb.png",
  "saveVersion": 1,
  "leaderboard": { "enabled": true, "order": "desc", "label": "Punkte" },
  "leaderboardSeason": 1
}
  • order: "desc" = mehr ist besser, "asc" = weniger ist besser (z. B. Zeit).
  • leaderboardSeason erhöhen, wenn ein Update das Spiel deutlich leichter oder schwerer macht – dann beginnt eine neue Bestenliste, die alte bleibt abrufbar.
  • Der Autor kommt immer aus deinem Benutzernamen, nicht aus der game.json.

Prompt-Block zum Kopieren

In deinen KI-Prompt einfügen, zusätzlich zur Beschreibung deines Spiels. 
Baue das Spiel als statische Web-App für die Spielebibliothek:
- index.html im Hauptordner, alle Pfade relativ (./…), keine CDNs, alle Bibliotheken als Datei mitliefern, kein Server-Code, keine Netzwerkaufrufe nach außen.
- Binde <script src="/lib/gamesave.js"></script> als erstes Script ein und speichere Fortschritt mit await GameSave.save(key, data) / const {data, version} = await GameSave.load(key). Fange Fehler von GameSave ab. GameSave.available ist false beim lokalen Testen – das Spiel muss trotzdem laufen.
- Für Highscores: await GameSave.submitScore(zahl) und await GameSave.leaderboard() (Liste von {player, score}).
- Lege eine game.json an: {"title": "...", "description": "...", "thumbnail": "thumb.png", "saveVersion": 1, "leaderboard": {"enabled": true, "order": "desc", "label": "Punkte"}, "leaderboardSeason": 1} und erstelle ein Vorschaubild thumb.png oder thumb.svg im Format 16:9.
- Wenn du Elemente mit dem hidden-Attribut ein- und ausblendest, ergänze im CSS [hidden] { display: none !important; } – sonst bleiben Overlays mit display:flex/grid sichtbar.
- Ändere bei späteren Updates die Struktur gespeicherter Daten nie ohne Migration: neue Felder mit Standardwerten, nichts umbenennen oder löschen. Wenn sich die Struktur ändert, erhöhe saveVersion und wandle alte Stände beim Laden um.
- Nur diese Dateitypen verwenden: html, js, css, json, png, jpg, gif, webp, svg, mp3, ogg, wav, woff2, wasm, glb, gltf.

Häufige Fragen

Mein Spiel zeigt nur eine weiße Fläche.
Meist ein absoluter Pfad (/assets/…) oder eine Bibliothek vom CDN. Beides geht hier nicht – siehe Regeln 2 und 4.
Ein Overlay oder Menü verschwindet nicht.
Siehe die hidden-Zeile im Prompt-Block.
Mein Spielstand ist nach einem Update weg.
Wurde ein anderer Ordnername verwendet? Sonst bei Seb melden – die letzten 5 Stände jedes Spielstands sind gesichert.
Die Seite sagt „Anmeldung abgelaufen“.
Nach einer Woche ist ein neuer E-Mail-Code nötig – Seite neu laden.
